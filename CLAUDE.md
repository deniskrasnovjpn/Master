# Глобальные правила

Файл общий для облачных и локальных сессий Claude Code. Пункты, относящиеся только к одной среде,
помечены: **[облако]** — сессия на claude.ai/code в облачной Linux-VM (Ubuntu, bash) со свежим
клоном репозитория; **[локально]** — сессия на моём компьютере (Windows 11, PowerShell 7).
Пункты без пометки действуют в обеих средах. Отвечать по-русски, если я не прошу иначе.

## Вопросы

- Любая вопросительная формулировка — запрос информации, а не поручение.
  Исключений нет. Отвечать текстом, ничего не менять.
- Структура ответа: (1) прямой ответ; (2) при необходимости — рекомендация
  и варианты; (3) конкретное предложение в конце: «Сделать X?».
- Ответ на «как сделать X?» не является разрешением сделать X.
- «Можешь сделать X?» — вопрос о возможности, а не поручение: ответить
  и предложить, но не делать.
- Без спроса разрешено: чтение файлов, поиск, любые read-only проверки —
  всё, что нужно для точного ответа.
- Команда — это императив («сделай», «перенеси», «добавь», «исправь») или
  моё подтверждение после твоего вопроса. Всё остальное — вопрос.

## Git

- **[облако]** Все git-операции выполнять автоматически, без согласования: коммит, push,
  слияние с `main`.
- **[локально]** Каждая сессия работает в своей ветке: если сессия началась на `main`, перед
  первым изменением создать рабочую ветку. В рабочей ветке всё выполнять автоматически, включая
  коммиты и push этой ветки. Слияние с `main` и push в `main` — только по согласованию со мной.

## Пути и проектные правила

- Пути к файлам внутри репозитория всегда указывать относительными (от корня репозитория):
  в файлах проекта, скриптах, конфигах и ссылках.
- Правила проекта — в `CLAUDE.md` репозитория; при расхождении с этим файлом в вопросах проекта
  приоритет у проектного `CLAUDE.md`, в вопросах общения — у этого файла.

## Синхронизация правил и скиллов

- Этот файл, глобальные облачные скиллы (папка `skills/` и список `skills-upstream.txt`) и скрипты
  настройки хранятся в репозитории `deniskrasnovjpn/Master`. Правила менять только там.
  Файл держать короче 9 500 символов, иначе hook не сможет передать его целиком.
- **[облако]** Локальных путей моего компьютера (`C:\…`, `~/.claude/…` на Windows) в сессии нет.
  Всё, что не закоммичено и не запушено, при окончании сессии теряется: временные файлы,
  установленные пакеты, промежуточные результаты; нужное для продолжения работы сохранять
  в репозитории и по завершении задачи коммитить и пушить без запроса (см. «Git»).
  Если для задачи нужен инструмент, которого нет в окружении, сначала сказать об этом и предложить
  установку (и запись в скрипт настройки проекта, если он есть), а не обходить молча.
- **[облако]** В поле Setup script облачного окружения — только заглушка (`setup-stub.sh`), которая
  клонирует Master и запускает `setup.sh`. Платформа выполняет её лишь при сборке снимка
  окружения (первая сессия, изменённое поле, истечение снимка примерно через неделю), а новые
  сессии стартуют из снимка. Поэтому `setup.sh` ставит инструменты (apt-get, pip, npm) и hook
  SessionStart, который при каждом старте сессии подтягивает из Master свежие скиллы и, если этот
  файл изменился, его актуальный текст. Все команды настройки добавлять в `setup.sh`; правки
  правил и скиллов доходят до следующей сессии сами, а после изменения инструментов в `setup.sh`
  надо сменить строку `# rev` в поле окружения.
- **[локально]** `~/.claude/CLAUDE.md` содержит только импорт этого файла из копии Master
  `~/.local/share/claude-master`. Её при каждом старте сессии обновляет hook SessionStart
  (`~/.claude/hooks/master-session-start.sh --skills-only`), он же синхронизирует скиллы Master
  в `~/.claude/skills/`; правка в Master вступает в силу со следующей сессии. Копию в
  `~/.local/share/claude-master` не редактировать (hook сбрасывает её на `origin`); для правок —
  клон `C:\Users\Denis\Documents\AI-Projects\Master`.

## Окружение пользователя

- Мой компьютер: Windows 11, все приложения Windows — на **английском** языке (названия меню,
  кнопок, настроек давать по-английски). Команды, которые я выполняю у себя, давать для
  PowerShell 7 (Git Bash — вторичная оболочка). **[облако]** Команды внутри сессии — bash.
- **[локально]** Свои команды выполнять через Bash (Git Bash): файлы, текст, git, скрипты.
  PowerShell — только для Windows-специфичного: реестр, службы, процессы, настройки системы,
  `.ps1`-скрипты, команды, которые я потом повторю у себя.
- Android-устройства (телефон, планшет) — интерфейс на **немецком** языке (названия пунктов меню
  и настроек давать по-немецки, при необходимости с переводом).
- Тексты, которые я отправлю или опубликую от своего имени (письма, сообщения, статьи, посты):
  сначала прочитать `~/.claude/skills/my-writing-style/SKILL.md` и следовать ему. Это мой профиль
  стиля из `skills/my-writing-style/` в Master; hook затирает копию в `~/.claude/skills/`, поэтому
  правки профиля вносить в Master и пушить по правилам «Git». Репозиторий публичный: без личных данных.

## Скиллы

- Выбирай скиллы по `description` их `SKILL.md`; явно указанный мной скилл имеет приоритет.
- Откуда сессия берёт скиллы:
  - **[облако]** скиллы, включённые на claude.ai; скиллы Master (копируются в `~/.claude/skills/`
    VM при старте сессии); `.claude/skills/` текущего репозитория. Скиллов с моего компьютера нет.
  - **[локально]** скиллы, включённые на claude.ai; `~/.claude/skills/` — глобальные скиллы
    компьютера вместе с синхронизированными туда скиллами Master; `.claude/skills/` текущего
    репозитория и родительских каталогов до его корня; скиллы плагинов.
- По умолчанию скилл ставится глобально в облако. Глобально на компьютер или локально в репозиторий
  ставятся только скиллы, которые в облаке выполнить невозможно, бессмысленно или бесполезно
  (например, работающие с программами, файлами или устройствами моего компьютера).
- «Установить скилл глобально в облако» — положить его папку в `skills/` репозитория
  `deniskrasnovjpn/Master` или, если скилл берётся из GitHub-репозитория, добавить строку
  в `skills-upstream.txt`; закоммитить и запушить (**[локально]** push в `main` — по согласованию,
  см. «Git»). **[облако]** Для текущей сессии ещё и скопировать его в `~/.claude/skills/`.
  **[облако]** `npx skills add -g` для этого не подходит: он ставит скилл только в
  `~/.claude/skills/` текущей VM, и скилл пропадёт вместе с сессией.
- «Установить скилл глобально на компьютер» — положить его в `~/.claude/skills/` моего компьютера.
  **[облако]** Это невозможно: сказать об этом и предложить установку в облако или в репозиторий.
- «Установить скилл локально» — положить его в `.claude/skills/` текущего репозитория.
- Если скилл вызывает другой скилл, ставить оба. Режим по умолчанию — обычный (без
  `disable-model-invocation`), если я не попрошу иначе.

## Тексты для людей

- Любой текст, который могут показать другим людям (письма, сообщения, текст магистерской,
  отчёты, посты и т. п.), перед тем как отдать мне, обязательно проверять и править скиллом
  `humanizer`. Это касается и новых текстов, и правок уже готовых.

## Поиск

- Библиотеки, API, фреймворки, SDK, CLI, облачные сервисы (синтаксис, настройка, версии, ошибки)
  и код с ними: сначала Context7 (`resolve-library-id` → `query-docs`), сам, без моего указания,
  даже если ответ кажется известным; не нашлось — веб-поиск по правилам ниже. Context7 — только
  коннектор claude.ai (**[локально]** синхронизированный из приложения); другие его установки
  (плагины, MCP-серверы, скиллы) не ставить.
- Простой поиск в интернете (один факт, известный сайт, короткая справка, чтение страницы
  по URL): встроенные `WebSearch`/`WebFetch`.
- Tavily (коннектор claude.ai, префикс инструментов бывает разным) — только для запросов сложнее
  среднего: исследование темы по многим источникам, сравнение и сводка, малоизвестные или свежие
  сведения, где `WebSearch` дал скудный результат, страницы, с которыми не справился `WebFetch`,
  обход сайта. В этих случаях:
  - исследование, сравнение вариантов → `tavily_research`: развёрнутое описание задачи в `input`;
    `model`: `mini` — узкая тема, `pro` — широкая со многими подтемами, `auto` — по умолчанию;
    лимит 20 запросов/мин;
  - список ссылок и фактов → `tavily_search`: `time_range` (`day`/`week`/`month`/`year`) или
    `start_date`/`end_date` для свежести; `include_domains`/`exclude_domains` для конкретных
    сайтов; `max_results` больше 5 для широких тем; `search_depth: "advanced"` для сложных
    запросов; `country` полным именем (`Germany`, не `de`); `exact_match` для точных фраз;
    `include_raw_content`, когда нужен полный текст;
  - страница, с которой не справился `WebFetch` → `tavily_extract`: `extract_depth: "advanced"`
    для LinkedIn, таблиц, защищённых страниц; `format` `markdown`/`text`; `query` для
    переранжирования кусков;
  - обход сайта → `tavily_crawl` (с контентом) или `tavily_map` (только URL): `instructions`
    на естественном языке, `max_depth`/`max_breadth`/`limit` под объём,
    `select_paths`/`exclude_paths` (regex) для нужных разделов.
- Всегда приводить источники (URL) в ответе.
