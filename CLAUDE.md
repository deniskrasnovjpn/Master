# Глобальные правила (облачная версия)

Эта версия предназначена для Claude Code в облаке (claude.ai/code). Сессия работает не на моём
компьютере, а в облачной Linux-VM (Ubuntu, bash) со свежим клоном репозитория.

## Вопросы

- Любая вопросительная формулировка — запрос информации, а не поручение.
  Исключений нет. Отвечать текстом, ничего не менять.
- Структура ответа: (1) прямой ответ; (2) при необходимости — рекомендация
  и варианты; (3) конкретное предложение в конце: «Сделать X?».
- Ответ на «как сделать X» не является разрешением сделать X.
- «Можешь сделать X?» — вопрос о возможности, а не поручение: ответить
  и предложить, но не делать.
- Без спроса разрешено: чтение файлов, поиск, любые read-only проверки —
  всё, что нужно для точного ответа.
- Команда — это императив («сделай», «перенеси», «добавь», «исправь») или
  моё подтверждение после твоего вопроса. Всё остальное — вопрос.

## Стиль письма
- Формулы писать в LaTeX: выносные — блоком `$$…$$` на отдельных строках, встроенные в текст — в `$…$`; не заменять формулы Unicode-текстом, если я не прошу иначе.
- В строчных формулах индексы всегда в фигурных скобках (`$a_{i}/b_{j}$`, не `$a_i/b_j$`):
  иначе два подчёркивания чат принимает за курсив Markdown, и формула не отрисовывается.
- Отвечай по-русски, если я не прошу иначе.
- Пиши связными предложениями естественной длины, в любом языке и в любом
  тексте.

## Работа в облаке

- Всё, что не закоммичено и не запушено, при окончании сессии теряется: временные файлы,
  установленные пакеты, промежуточные результаты. Нужное для продолжения работы сохранять
  в репозитории и по завершении задачи коммитить и пушить без запроса (см. «Git»).
- Локальных путей моего компьютера (`C:\…`, `~/.claude/…` на Windows) в сессии нет; в файлах проекта
  использовать только относительные пути.
- Если для задачи нужен инструмент, которого нет в окружении, сначала сказать об этом и предложить
  установку (и запись в скрипт настройки проекта, если он есть), а не обходить молча.
- Правила проекта — в `CLAUDE.md` репозитория; при расхождении с этим файлом в вопросах проекта
  приоритет у проектного `CLAUDE.md`, в вопросах общения — у этого файла.
- Этот файл, глобальные скиллы и скрипт настройки окружения (`setup.sh`) хранятся в репозитории
  `deniskrasnovjpn/Master`. В поле Setup script облачного окружения — только заглушка
  (`setup-stub.sh`), которая клонирует Master и запускает `setup.sh`. Платформа выполняет её
  лишь при сборке снимка окружения (первая сессия, изменённое поле, истечение снимка примерно
  через неделю), а новые сессии стартуют из снимка. Поэтому `setup.sh` ставит инструменты
  (apt-get, pip) и hook SessionStart, который при каждом старте сессии подтягивает из Master
  свежие скиллы и, если этот файл изменился, его актуальный текст. Все команды настройки
  добавлять в `setup.sh`; правки правил и скиллов доходят до следующей сессии сами, а после
  изменения инструментов в `setup.sh` надо сменить строку `# rev` в поле окружения. Этот файл
  держать короче 9 500 символов, иначе hook не сможет передать его целиком.

## Git

- Облачные сессии: все git-операции выполнять автоматически, без согласования — коммит, push,
  слияние с `main`.
- Локальные сессии (на моём компьютере): коммит в рабочую ветку — автоматически; слияние с `main`
  и push — только по согласованию со мной.

## Окружение пользователя

- Мой компьютер: Windows 11, все приложения Windows — на **английском** языке (названия меню, кнопок,
  настроек давать по-английски). Команды, которые я должен выполнить у себя, давать для PowerShell 7
  (Git Bash доступен как вторичная оболочка); команды внутри облачной сессии — bash.
- Android-устройства (телефон, планшет) — интерфейс на **немецком** языке (названия пунктов меню
  и настроек давать по-немецки, при необходимости с переводом).
- Кодинг-агенты: Claude Code, **Antigravity** и **Codex** (CLI и app). **Gemini CLI не используется** —
  не предлагать его, не давать команды `gemini …` и не устанавливать туда скиллы/расширения.

## Скиллы

- Мои локальные скиллы с компьютера в облаке недоступны. Доступны скиллы, включённые на claude.ai,
  глобальные скиллы из папки `skills/` репозитория `deniskrasnovjpn/Master` (копируются
  в `~/.claude/skills/` при старте сессии) и скиллы из `.claude/skills/` текущего репозитория.
  Выбирай скиллы по `description` их `SKILL.md`; явно указанный мной скилл имеет приоритет.
- «Установить скилл глобально» — положить его в папку `skills/` репозитория `deniskrasnovjpn/Master`
  (подключить этот репозиторий к сессии, если его нет), закоммитить и запушить, а для текущей сессии
  ещё и скопировать в `~/.claude/skills/`. Команда `npx skills add -g` для этого не подходит: она ставит
  скилл только в `~/.claude/skills/` текущей облачной VM, и он пропадёт вместе с сессией.
- «Установить скилл локально» — положить его в `.claude/skills/` текущего репозитория.
- Если скилл вызывает другой скилл, ставить оба. Режим по умолчанию — обычный (без
  `disable-model-invocation`), если я не попрошу иначе.

## Поиск

- Документация библиотек, API, фреймворков, CLI: скилл `find-docs` (Context7), если он доступен.
- Поиск в интернете: Tavily MCP (`mcp__tavily-remote-mcp__*`), если он подключён (через `.mcp.json`
  репозитория или коннектор claude.ai); иначе встроенные `WebSearch`/`WebFetch`.
- Выбор инструмента Tavily: исследование темы из многих источников → `tavily_research` (`model`: `mini` —
  узкая тема, `pro` — широкая, `auto` по умолчанию); список ссылок и фактов → `tavily_search`; конкретные
  URL → сразу `tavily_extract`; обход сайта → `tavily_crawl` или `tavily_map`.
- Всегда приводить источники (URL) в ответе.
